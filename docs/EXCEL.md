# 수불자료 엑셀 — 양식과 검증 규칙

파서: `src/lib/excel/parseSubul.ts`, `src/lib/excel/parseQuantity.ts`
테스트: `node src/lib/excel/parseQuantity.test.mjs`

---

## 1. 양식

실제 장부에는 **제품코드·재료코드 열이 없다.** 그래서 전부 이름으로 맞춘다.

```
시트 하나 = 제품 하나.  시트 이름이 곧 제품명 ('포기김치', '맛김치')

   A          B          C          D
1  포기김치                                     ← 제목 행 (사람이 보는 용도)
2
3  품명       수량(kg)   단가(원)   금액(원)     ← 헤더. 3행 또는 4행
4  배추       606,248    865        =B4*C4
5  무          50,847    508        =B5*C5
   ...
12 합계                             =SUM(D4:D11)
```

`금액` 열은 **수량 × 단가 수식**이다. 내려받는 양식(`public/수불자료_양식.xlsx`)도
같은 수식을 갖고 있어서 수량·단가만 채우면 금액이 따라온다.
`scripts/build-subul-template.mjs` 로 다시 만든다.

| 규칙 | 내용 |
|---|---|
| 시트 건너뛰기 | 이름에 `템플릿` `양식` `샘플` `안내` `가이드` 가 들어가면 무시 |
| 헤더 찾기 | 위에서 15행 안에서 `품명`+`수량`+`단가` 가 다 있는 행 |
| 품명 별칭 | `품명` `품목` `재료명` |
| 수량 별칭 | `수량` `사용량` `투입량` |
| 종료 | `합계` `계` `총계` 행을 만나면 그 시트 끝 |
| 빈 자리 | `품명 작성` 은 템플릿 잔재이므로 무시 |
| 금액 열 | **읽기만 하고 저장하지 않는다** |

### 금액 열을 쓰지 않는 이유

DB의 `amount` 는 generated 컬럼(`수량 × 단가`)이다.
수불자료가 손글씨 전사본이라 장부 금액이 틀린 경우가 실제로 있었다
(포기김치 249만원 차이 확인). 장부 금액은 검증용으로만 읽어
`findAmountMismatches()` 에서 1원 초과 차이를 보고한다.

## 2. 매칭

| 엑셀 | DB | 실패 시 |
|---|---|---|
| 시트 이름 | `products.name` | `missingProducts` → "이 제품들 등록하기" 버튼 |
| 품명 | `materials.name` | `missingMaterials` → "이 재료들 등록하기" 버튼 |

비교는 **공백 제거 + 소문자화** 후에 한다.
`고춧가루 (국)` 과 `고춧가루(국)` 은 같게 본다. 그 외 오타는 잡지 못한다.

등록 버튼을 누르면 같은 파일을 자동으로 다시 읽어 매칭 상태를 갱신한다.
재업로드할 필요가 없다.

## 3. 수량 단위 검증

`material_usages` 는 **kg으로만 저장한다** (`commitSubul` 이 `unit: 'kg'` 고정).
따라서 kg으로 바꿀 수 없는 단위는 받을 수 없다.

### 통과 — 그대로

`606248` · `1,234.5` · `1 234` · `12.5kg` · `5 KG` · `5kg(정미)`

숫자만 있으면 헤더 단위(기본 kg)로 본다.
괄호·슬래시 뒤 설명은 떼어낸다.

### 통과 — 환산 + 경고

| 입력 | 저장값 |
|---|---|
| `300 g` `300그램` | 0.3 kg |
| `2 ton` `2톤` | 2000 kg |

별칭: `kg KG 킬로 킬로그램 키로` / `g gram grams 그램` / `t ton tons 톤`

### 차단 — 오류

| 입력 | 이유 |
|---|---|
| `20개` `3박스` `10 EA` `5팩` `2상자` | 개수 단위. kg으로 환산할 방법이 없다 |
| `10L` `500ml` `3리터` | 부피 단위. 비중을 모른다 |
| `미상` `-5` `10말리` | 숫자가 아님 / 음수 / 알 수 없는 단위 |

### 헤더 단위 선언

헤더가 `수량(g)` 이면 **그 시트 전체**를 그램으로 보고 환산한다.
셀에 붙은 단위가 헤더보다 우선한다 (`수량(g)` 시트의 `2kg` → 2 kg).

### 단가 칸

`1,200원` `₩1,200` `1200 원/kg` 모두 1200으로 읽는다.
통화·단위 표기는 정보가 없으므로 떼어낸다.

## 3-1. 기준 월 확인

엑셀 **안에는 월이 적혀 있지 않다.** 시트에도 헤더에도 없다.
따라서 어느 달 자료인지는 화면 우측 상단에서 고른 기준 월이 전부다.

파일명이 유일한 단서라서, `monthFromFileName()` 이 이를 읽어
선택한 월과 다르면 미리보기에 노란 경고를 띄운다.

| 파일명 | 추측 |
|---|---|
| `수불자료_테스트_26.09.xlsx` | 2026-09 |
| `수불자료_2026-09.xlsx` | 2026-09 |
| `수불자료.xlsx` | 없음 — 경고하지 않음 |

확실한 정보가 아니므로 **저장을 막지는 않는다.**
경고 안의 "N월로 바꾸기" 버튼으로 기준 월을 한 번에 맞출 수 있다.

## 4. 경고 vs 오류

| | 뜻 | 저장 |
|---|---|---|
| `warnings` | 넘어가도 되는 것 — 빈 행, 단위 환산 알림, 헤더 못 찾은 시트 | 가능 |
| `errors` | 사람이 엑셀을 고쳐야 하는 것 — 값이 있는데 해석 실패 | **차단** |

`errors` 가 하나라도 있으면:

- 미리보기에 빨간 "오류 N건" 배지 + 행 단위 목록
- 저장 버튼 잠김 → "오류를 수정한 뒤 다시 올려주세요"
- `commitSubul()` 이 자체적으로도 거부 (UI 우회 방지)

### 왜 이렇게 나눴나

예전 파서는 `10kg` 을 `NaN` → `null` 로 흘리고
**"수량 또는 단가가 비어 있어 건너뛰었습니다"** 라고 보고했다.
값이 멀쩡히 적혀 있는데 "비어 있다"고 하니,
**재료 하나가 빠진 채로 원가가 확정될 수 있었다.**

더 위험한 건 그램 값이 통과했다면 1000배 오차가 났을 것이라는 점이다.

## 5. 저장

```
material_usages  upsert on (period_id, product_id, material_id)
```

같은 달에 파일을 다시 올리면 덮어쓴다. 중복 행이 쌓이지 않는다.
매칭된 행만 저장하고, 미매칭 제품·재료의 행은 건너뛴다.

원본 파일은 `excel-uploads`(Private) 버킷에 보관되고
`file_uploads` 에 업로더·행 수와 함께 기록된다.

> 저장이 `42501` 로 실패하면 대개 **그 달이 이미 마감**된 것이다.
> 권한 문제가 아니다. 3단계에서 마감을 취소해야 한다.
